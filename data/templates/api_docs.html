TARR Annunciator API Documentation

REST API for external systems and scripts (v1.1.2).

This page requires an Admin login. It is served at /admin/api-docs (legacy /api/docs uses the same auth gate).

Authentication

Most /api/… write/control endpoints require an API key configured under Admin → User & API Management.

  • Header (preferred): X-API-Key: YOUR_API_KEY
  • Query: ?api_key=YOUR_API_KEY
  • Form field: api_key=YOUR_API_KEY

Replace YOUR_API_KEY with a key from Admin. Do not hard-code production keys into public repos.

Red Alert behavior

While a Thor Guard Red Alert lock is active and non-emergency suppress is enabled, station / promo / safety / scheduled announcements are rejected with HTTP 409 Conflict and red_alert_active: true. Emergencies and lightning audio still follow their own rules.

Public endpoints no API key

Example response: 
{

  "app_version": "1.1.2",
  "installed_version": "1.1.2",
  "audio_available": true,
  "audio_backend": "beep",
  "api_enabled": true,
  "scheduler_running": false,
  "operating_hours": {
    "hours_enabled": true,
    "scheduler_active": false,
    "label": "Paused (outside operating hours)",
    "timezone": "America/New_York",
    "local_time": "2026-09-20 21:00:00 EDT",
    "within_hours": false
  },
  "volume": 70,
  "selected_audio_device": "default",
  "available_devices": 2,
  "platform": { "...": "platform details" },
  "timestamp": "2026-09-20T21:00:00-04:00"
}

GET /api/platform

Host platform details (OS / arch / Raspberry Pi hints). Useful for installers and support.

Announcements API key

Accept JSON (Content-Type: application/json) or form fields. Values for trains / destinations / etc. must match IDs from GET /api/config.

POST /api/announce/station

Queue a station (train) announcement.

JSON body: 
{
  "train_number": "1",
  "direction": "westbound",
  "destination": "goodwin_station",
  "track_number": "1"
}

Optional form fields: priority (default normal), delay seconds.

POST /api/announce/safety

Queue a safety announcement.

JSON body: 
{
  "language": "english"
}

Optional: priority (default high), delay.

POST /api/announce/promo

Queue a promo announcement. file is the promo ID (not necessarily including .mp3 — use IDs from config).

JSON body: 
{
  "file": "promo_english"
}

Optional: priority (default low), delay.

POST /api/announce/emergency

Queue an emergency announcement at highest priority. file must be an emergency ID from config (e.g. severe_weather).

JSON body: 
{
  "file": "severe_weather"
}

Queue controls API key

POST /api/announcements/pause

Pause the announcement queue (does not clear waiting items).

POST /api/announcements/resume

Resume a paused queue.

POST /api/announcements/stop-current

Stop the announcement that is currently playing.

Audio API key

GET /api/audio/volume

Returns volume (0.0–1.0), volume_percent, and system_mixer status on Linux.

POST /api/audio/volume

Set volume. Accepts 0.0–1.0 or 0–100. On Raspberry Pi / Linux also updates ALSA mixer levels and persists for reboot.

{ "volume": 75 }

GET /api/audio/devices

List detected audio output devices and the currently selected device.

POST /api/audio/devices

Select an output device by ID (from the devices list).

{ "device_id": "default" }

Configuration & schedule API key

GET /api/config

Catalogs used by announcements: trains, directions, destinations, tracks, promo list, safety languages, emergencies.

GET /api/schedule

Returns the current cron schedule object (station_announcements, promo_announcements, safety_announcements).

POST /api/schedule

Replace the schedule. Body must wrap the cron object:

{
  "schedule": {
    "station_announcements": [],
    "promo_announcements": [],
    "safety_announcements": []
  }
}

On success the in-process scheduler is rebuilt. Jobs still respect operating hours.

Lightning / Thor Guard API key

Multi-feed monitor (primary + failover_1 + failover_2), Red Alert lock, All Clear release modes, condition audio. Prefer Admin UI for day-to-day changes; use these endpoints for automation.

GET /api/lightning/status

Full lightning trigger status (same rich payload Admin uses), including:

  • active_feed_id, active_displayname, on_failover
  • last_condition, red_alert_active, reminder fields
  • feeds, failover, feed_health (includes last_alert)
  • allclear_release_mode (primary_only | failover_vote)
  • entered_red_alert_on_feed, condition_announce, condition_audio, red_alert_policy

POST /api/lightning/config

Update lightning configuration by section (same handler as Admin). Sections:

  • monitor (default) — timing, failover, feeds, feed-switch rules, announce timing
  • condition_announce — which conditions may PA
  • condition_audio — horn + voice MP3 pairs
  • red_alert_policy — preempt / suppress / reminder
Example — set All Clear release mode: 
{
  "section": "monitor",
  "enabled": true,
  "fetch_interval": 60,
  "timeout": 30,
  "failover": {
    "consecutive_failures": 5,
    "failback_mode": "prefer_primary",
    "failback_after_successes": 5,
    "allow_failover_during_red_alert": true,
    "allclear_release_mode": "primary_only",
    "preserve_condition_across_failover": true,
    "on_all_feeds_failed": "hold_last_condition",
    "triggers": {
      "http_error": true,
      "http_status_not_ok": true,
      "empty_body": true,
      "encoding_error": true,
      "missing_lightningalert": true,
      "unknown_condition": true,
      "displayname_mismatch": false,
      "uniqueid_mismatch": false
    }
  },
  "feeds": [ "... full feed objects ..." ]
}

Send a complete monitor payload when updating feeds/failover (Admin does this). Partial objects may disable feeds if omitted incorrectly.

POST /api/lightning/test/:condition

Manual condition test / drill. :condition is one of: RedAlert, AllClear, Warning, Caution, Unknown (case-insensitive).

Plays audio and can engage Red Alert lock — use carefully on a live PA.

Queue status Admin session cookie

These routes use requireAuth() (browser Admin login), not the API key middleware. They power the Admin Announcement Queue tab.

GET /api/queue/status

Current queue state (running / paused / playing / waiting).

GET /api/queue/history?limit=20

Recent announcement history. Optional limit (default 20).

POST /api/queue/cancel

Cancel a queued item by ID.

{ "id": "announcement-id-here" }

Related public HTTP helpers no API key

Not under the /api group, but useful for dashboards and kiosks.

GET /lightning_status

Public subset of lightning status for the Main Control Dashboard: lock, condition, active feed, feed health, allclear_release_mode, etc.

GET /scheduler_status

Scheduler jobs, audio_available, and operating_hours label (same wording as Admin / Main header).

GET /audio_status

Audio availability, volume, mixer summary, chime presence.

POST /play_announcement

Form-based station play used by the Main UI (not API-key gated).

POST /play_promo

Form-based promo play (Main UI).

POST /play_safety_announcement

Form-based safety play (Main UI).

Common errors

HTTPWhen
400Missing/invalid fields, bad JSON, unknown promo/emergency/language ID
401 / redirectAdmin session required (docs page, queue status routes)
409Announcement suppressed by active Red Alert lock
503API disabled in configuration (api_enabled false)
403 / 401Missing or invalid API key on authenticated /api routes

Admin-only UI routes (/admin/lightning/…, updates, Bluetooth, users, etc.) are not fully enumerated here — they require a browser Admin session and power the Admin tabs. Use this document for external integration via /api.

curl examples

Replace HOST (e.g. 10.81.77.159:8080 or localhost:8080) and YOUR_API_KEY.

Status (public): 
curl -s http://HOST/api/status
Station announcement: 
curl -X POST http://HOST/api/announce/station \
  -H "X-API-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"train_number":"1","direction":"westbound","destination":"goodwin_station","track_number":"1"}'
Lightning status: 
curl -s http://HOST/api/lightning/status \
  -H "X-API-Key: YOUR_API_KEY"
Pause queue: 
curl -X POST http://HOST/api/announcements/pause \
  -H "X-API-Key: YOUR_API_KEY"
Public lightning dashboard subset: 
curl -s http://HOST/lightning_status
